Events and data behavior

Other browser-side services can inject the tracking service and record an application event:

The service stores a random visitor ID in {{ context.codeblock7 }} and a session ID in {{ context.codeblock8 }}. Reloads reuse the session; 30 minutes without recorded activity starts a new session. Navigation completions record page views, and pointer/keyboard activity is throttled. Timestamps come from the backend. Durations are approximate; there is no unload beacon or background session expiry job. No fingerprinting or user-agent parsing is performed.

Backend packages can inject {{ context.codeblock9 }} and call {{ context.codeblock10 }}. Event names share one generic event table; backend-originated events may omit visitor, session, and user associations. Authenticated user IDs are derived from verified Taon session tokens, not from the collection payload.

Permissions and runtime

Baseline shows Analytics navigation to superusers or users with {{ context.codeblock11 }}. The Angular tracking service runs in the browser; the analytics context, repositories, and backoffice APIs run in the configured Taon backend. WebSQL browser mode changes where backend code executes, so verify that the selected database and storage behavior is appropriate before using it as a production analytics store.
