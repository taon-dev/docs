Use the backoffice

The CMS navigation provides post, course, category, tag, asset, comment, and content-permission features. Posts support published or draft content, related posts, thumbnails, revisions, and media attachments. Categories can be nested; tags are flat. Product pages can link to CMS posts, and course components can render a protected post and its related lessons; see e-commerce.

The backoffice's CMS entry is visible to superusers or users with {{ context.codeblock9 }}. Individual controllers can apply finer checks such as {{ context.codeblock10 }}; grant the relevant permission through Taon authorization rather than relying on a hidden menu item as the security boundary. CMS APIs also enforce their own access and publication rules.

Storage assets are accessed through Taon storage APIs. For example, the Assets page lists stored files and requests short-lived private URLs rather than buffering file contents in the browser. Configure the storage backend and public/private access policy for the deployment target.

Runtime notes

The Angular backoffice runs in the browser. Its context and data APIs must be registered on the application's Taon backend. WebSQL mode places backend work in the browser, so it is not a substitute for a server when the application needs server-managed credentials or externally reachable media URLs. Check the selected storage provider's support before enabling CMS uploads in WebSQL or a Cloudflare Worker.
