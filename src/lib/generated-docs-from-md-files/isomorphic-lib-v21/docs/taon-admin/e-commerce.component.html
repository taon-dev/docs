Use products, cart, and courses

Create products in E-commerce > Products, configure price and availability, and optionally use Link to post to use a CMS post for the product details. Customers add eligible products to the cart and complete checkout. Product eligibility is checked on the server for ownership, active subscriptions, stock, pending reservations, per-user limits, currency, and recurring checkout compatibility.

The course components can display a public CMS root and its protected related lessons. The CMS post's related-post order is preserved. Purchased media is authorized by the server's session and entitlement-aware auth repository; a browser-provided authorization context is only a refresh trigger.

Permissions and runtime

Baseline shows the e-commerce menu to superusers or users with the exact permission key {{ context.codeblock11 }}. Sensitive commerce operations are validated by their Taon controllers and repositories as well.

The Stripe secret and webhook flow require a server-side runtime with a reachable webhook endpoint. WebSQL may be useful for browser-local development or UI testing, but it does not provide a place to keep Stripe secrets or receive external Stripe webhooks. Cloudflare Worker deployments must configure Worker bindings and a reachable webhook route; verify database and provider support for that target before deploying.
