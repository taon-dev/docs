Taon Session

{{ context.codeblock0 }} supplies Taon login, registration, session state, and authorization. It also provides user, session, role, group, and authorization backoffice routes. It is designed for Taon applications, not as a standalone authentication package.

Main features and authorization

  • Session login and registration support Taon's JWT, cookie, and header authentication paths.
  • {{ context.codeblock7 }} can protect controller methods. Apply it before inherited middleware when the request must be authenticated first.
  • The session context exposes authorization checks for admin capabilities. Baseline's user, session, and authorization menu entries use {{ context.codeblock8 }}, {{ context.codeblock9 }}, and {{ context.codeblock10 }}; superusers can also see these entries.
  • CMS, commerce, SEO, and analytics use their own permission checks. Logging in alone does not grant administrator access.

Use the session state returned by the server as the source of authorization. Do not treat a client-provided user ID or permission list as proof of identity.

Runtime notes

Register the session context in the backend context that serves the application. Node.js and WebSQL are distinct Taon deployment modes; browser mode does not make server secrets available to browser code. Use the server environment for credentials and deployment-specific authentication configuration.
