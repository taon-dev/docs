Why Do I Need {{ context.codeblock0 }} to Develop Taon?

The {{ context.codeblock1 }} CLI serves as a backup development tool for Taon.

  • If you modify Taon's internal code, you might accidentally break the build system or CLI, making it impossible to build, release, or manage projects using the {{ context.codeblock2 }} command. The {{ context.codeblock3 }} CLI provides a fallback in such situations.
  • The {{ context.codeblock4 }} CLI provides more detailed diagnostic information than the standard {{ context.codeblock5 }} CLI.

CLI — Main Repository ({{ context.codeblock25 }})

Use this repository to:

  • Add or modify {{ context.codeblock26 }} and {{ context.codeblock27 }} CLI commands.
  • Extend or modify the build system.

You will see changes immediately in you {{ context.codeblock29 }} tool.

Framework — Main Repository ({{ context.codeblock30 }})

Use this repository to:

  • Develop and modify Taon framework building blocks.
  • Work with controllers, contexts, providers, repositories, and other framework components.

Core Helpers and Utilities ({{ context.codeblock32 }})

Use this repository to:

  • Add, modify, and test core utilities and helper functions.

HTTP Fetch Wrapper ({{ context.codeblock34 }})

Use this repository to:

  • Develop and maintain Taon's HTTP communication abstractions.
  • Modify the HTTP request and response handling mechanisms.

Advanced Helpers, Utilities, and Types ({{ context.codeblock36 }})

Use this repository to:

  • Develop and maintain higher-level utilities, classes, types, and reusable abstractions.

TypeORM Fork ({{ context.codeblock38 }})

Use this repository to:

  • Maintain and update Taon's TypeORM fork.
  • Apply framework-specific changes to TypeORM.

Taon UI ({{ context.codeblock40 }})

Use this repository to:

  • Develop and maintain reusable UI components.
  • Work on Taon's shared frontend components and abstractions.

Testing Your Changes in an Application

It is also useful to keep a second terminal open to run an actual application while developing.

This allows you to test your changes in a running application while the framework or module is being rebuilt in watch mode.
